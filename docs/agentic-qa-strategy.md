# Agentic QA strategy

How this repository uses AI agents in test automation: what they are trusted with, what went wrong when they were not checked, and which controls keep them honest. Every claim below points to a run that measured it, recorded in [`docs/phase-1/`](phase-1/) and the [learning log](ai-agents-learning-log.md).

**In one sentence:** agents read, map, draft and diagnose; deterministic code and people own every decision that changes what "green" means.

## 2. Where they are risky: seen here, not hypothetical

| Failure mode                       | Where           | What it looked like                                                                                                                                                                                           |
| ---------------------------------- | --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Confident false findings           | Phase 0         | A shared browser page leaked state and made four personas look broken; a fresh context per user showed the real, narrower defects                                                                             |
| Weakening a test to make it pass   | M6, M7          | Changing `'Cart, 1 item'` to the app's wrong `'Cart, 1 items'` passes every hook and lint rule, because no assertion disappears                                                                               |
| The model's priors as the oracle   | M10             | Without the catalogue and app model: "SauceDemo never disables Checkout on an empty cart ... so `toBeDisabled()` most likely contradicts the app model", a correct test called wrong                          |
| Anchoring on context               | M10             | The known defects of a persona framed a stale selector as a new product bug: 1 in 6 right on the two confusable cases                                                                                         |
| Silent false greens                | M8, Phase 0     | A stale selector made every `toBeHidden()` badge check pass vacuously; a skip guard with the wrong condition skipped a visual test on every run                                                               |
| Vacuous passes read as fixes       | Whole-run eval  | The same stale selector made two known-bug tests pass, and triage called SD-104 and SD-203 "maybe fixed"; until the report had to name the markers to remove, a right reading and a wrong one looked the same |
| Tools that decide                  | Whole-run eval  | The qa server read a timed-out known-bug test as a pass and told the agent to "remove the knownBug marker"; on an expired session the agent passed that on                                                    |
| Silent truncation                  | Whole-run eval  | The run summary cut 81 regressions at 50 and only its structured data said so: no persona failure reached the agent, and its report named 1 of 78 tests                                                       |
| Permission creep                   | M8              | A skill's `allowed-tools: Bash` let a headless agent run `curl` past an allowlist that named only npm scripts                                                                                                 |
| Reading the wrong evidence         | M9              | Triage of a failed nightly read today's `main`, not the failing commit, and could only guess where the wrong value came from                                                                                  |
| Untrusted input in CI              | M9              | In a pull request, the code, the agent's instructions and even the workflow come from the PR; reviewed code can carry instructions                                                                            |
| Rewriting the oracle               | Fix-loop eval   | Told only "make it pass", the agent re-created a deleted catalogue entry, re-documented the defect in the app model and marked the test: green on a bug nobody had approved                                   |
| Rules that drift from intent       | Review eval     | An exception written only in a code comment was flagged in 2 of 3 runs, and a second copy of the exception list, worded "do not flag ... the test ids", made 1 run in 3 pass both menu test-id traps          |
| Instructions taken literally       | Write-test eval | The skill listed `@smoke` among the suite tags with "exactly one", so a critical-path test got `@smoke` only and `npm run test:regression` would never have run it                                            |
| A skill that forbids its own steps | Write-test eval | `Bash(npm run *)` does not match `EXPOSE_KNOWN_BUGS=true npm run ...`, the command the skill prescribes; a run whose chained `grep` was denied twice stopped verifying and left a red, unmarked test          |
| Unequal comparisons                | Write-test eval | A plain prompt seemed to lose to the skill on formatting, 4 of 6; it had lacked the permission to run Prettier, and with the same tools it scored 6 of 6                                                      |
| Leaks in evaluation                | M7, M10         | Git status, auto memory shared across worktrees, lessons that describe injections, and a code seam each told the agent what it was being tested on                                                            |
| Cost and usage limits              | M10             | The first CI eval ran out of the subscription's usage limit after 25 of 35 cases                                                                                                                              |

## 3. Controls, in layers

No single layer is enough; each catches what the others cannot.

| Risk                              | Instruction                                                                                                              | Enforcement                                                                                                   | Detection                                                                                                                                                                            | Person                                     |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------ |
| Weakening tests                   | CLAUDE.md guardrail; `/fix-test` exit criteria                                                                           | `PreToolUse` hook (removed assertions, skip/only/fixme, `force`, waits); ESLint on the final state            | Zero-critical gates: the triage eval ("product bug called test bug") and the fix-loop eval (red turned green by hiding)                                                              | PR review of every diff                    |
| Rewriting the oracle              | `/fix-test`: a person decides whether a new defect gets an `SD-xxx` entry                                                |                                                                                                               | The fix-loop eval counts an agent-made catalogue entry as critical                                                                                                                   | Reviews every catalogue and app-model diff |
| Invented selectors and assertions | "Verify on the live app" rule                                                                                            | ESLint bans raw locators in specs                                                                             | Locator review; the verified app model as oracle                                                                                                                                     | Reviews the app model and new locators     |
| False greens                      | Assert the correct behaviour; mark defects with `knownBug()`; triage counts a pass as a fix only if its check could fail | Markers turn red when the bug is fixed                                                                        | Prove every check can fail (the write-test eval runs each new test where its behaviour breaks); read logs, not the green check; the whole-run eval's vacuous-pass and fixed-bug runs | Reads reports when numbers look odd        |
| Tool defects                      | Tools report, the agent and the person judge (no "remove the marker" from code)                                          | `eval:triage:check` compares the qa server's reading of every saved run with the eval's own, on every PR      | The whole-run eval grades the report the agent built from the tool's output; a cut list says that it is cut                                                                          |                                            |
| Untrusted input in CI             | Agents return data, never act                                                                                            | Read-only tools, `dontAsk`, no write token, `--json-schema`, deterministic posting; same-repo and label gates | Schema validation fails the job instead of posting nonsense                                                                                                                          | Adds the label after reading the diff      |
| Permission creep                  | Least privilege per skill and agent                                                                                      | Deny rules; scoped `allowed-tools`; auto mode refuses an agent's commits to its own configuration             | Headless probes of what a skill can reach                                                                                                                                            | Commits changes to agent configuration     |
| Wrong evidence                    | Triage the code that ran                                                                                                 | Checkout of `workflow_run.head_sha`; one worktree per agent                                                   | Vague diagnoses are a signal                                                                                                                                                         |                                            |
| Prompt and model regressions      |                                                                                                                          | The triage evals (single failures, whole runs) gate PRs that touch the agent, its prompt or its inputs        | Variants that should fail (no tools: 36%; Haiku on whole runs: known-bug ids missing), gates failed                                                                                  | Reviews the golden labels                  |
| Cost                              |                                                                                                                          | `--max-turns`, `--max-budget-usd`; path triggers; label gates; small models for mechanical work               | `total_cost_usd` in every report; inconclusive verdict on usage limits                                                                                                               | Chooses what is worth a run                |

## 4. A person in the loop: who decides what

- **People decide:** every merge (branch protection; agents cannot run `gh pr merge`); changes to permissions and agent configuration (an `ask` rule, and auto mode refuses to let the agent commit them); new known bugs and their `SD-xxx` ids; golden-set labels; visual baselines; whether a review or eval is worth running.
- **Agents propose, with evidence:** every report names the line that decides it (an `SD-xxx` id, an assertion diff, a selector in the app model), so a reviewer decides in a minute instead of re-investigating.
- **Code acts:** gates, schema checks, posting, and every classification that does not need judgment (flaky on retry, expected known-bug failures, stale markers).

## 5. Measuring it

- **Triage eval** (`npm run eval:triage`): 35 reviewed real failures; gate at 90% category and known-bug id accuracy, zero critical errors, in every repeat. Current: 34/35 on Sonnet and on Haiku (the miss is a borderline environment case), about $1.50 per run on Sonnet. Runs in CI when the agent or its inputs change.
- **Fix-loop eval** (`npm run eval:fix-loop`): `/fix-test` on 9 real failures (five test bugs, two catalogued and one uncatalogued product bug, an outage), each in its own isolated checkout, graded on what the loop changed and how the test ends, not on what it reports. Current: 9/9, no critical error, $1.61. A naive "make it pass" prompt with the same model, tools and hook failed the gate: it invented the missing catalogue entry. Run locally before changing `/fix-test`; it needs browsers and credentials, so it is not in CI.
- **Whole-run triage eval** (`npm run eval:triage:runs`): the nightly triage's own prompt and command line on 7 whole CI runs replayed from saved reports: a real green nightly (all browsers, 80 expected known-bug failures), a real run with a test bug, an expired session (78 failing tests, one cause), an outage, a stale selector that also makes two known bugs pass vacuously, a test bug and an uncatalogued product bug in one run, and a fixed known bug (the one synthesized report). Graded per test (is every test that needs action in the report, under the right category?) and on the decision the owner acts on: which `knownBug()` markers to remove, and no others. The first run passed every verdict but failed the gate: the report named 20 of 103 such tests, and the qa server had read a timeout as a fix. CI then caught what a local pass had missed: the report's contract left the vacuous passes out, and only a stale-marker field could tell a right reading from a wrong one. After the fixes: 100% in 3 of 3 repeats, and 7 of 7 on the two runs the marker call decides, about $0.50 per run on Sonnet. Runs in CI with the triage eval, and `eval:triage:check` keeps the qa server's reading of every saved run equal to the eval's.
- **Review eval** (`npm run eval:review`): the AI review's own prompt and command line on 13 small pull requests, 10 with 12 planted locator-rule violations that ESLint passes and 3 clean controls. Correct code that only looks wrong, such as a verified selector exception, must never be flagged: that is the critical error. The baseline caught 33 of 36 and flagged correct code twice; the causes were an exception written only in a code comment and a drifted second copy of the rules. After the fixes: 36 of 36 in 3 repeats, no correct code flagged, 1 false positive in 39 reviews, $0.07 for all of them on Haiku. Runs in CI when the reviewer, the rules or the page objects change.
- **Write-test eval** (`npm run eval:write-test`): `/write-test` on 6 behaviours, each in an isolated checkout with the specs that cover it removed: three that work for the standard user, two catalogued defects and one defect deleted from the catalogue. Graded on the tests it writes: lint, typecheck, format and the conventions, green on two normal runs, and red when the behaviour breaks, run as a persona whose catalogued defect breaks it or with known bugs exposed. A new test that stays green then, or a weaker suite, is a critical error. The baseline scored 5 of 6, and the next run 11 of 12; the misses came from a wrong tag instruction and a skill that did not permit a command it prescribed. After the fixes: 12 of 12 in 2 repeats, no critical error, $2.33 on Sonnet. A plain "write a test" prompt with the same tools scored 6 of 6: on these cases the rules, ESLint and the hook carry the conventions, so the eval guards the skill and the rules against regressions but shows no gain from the skill itself. Run locally before changing `/write-test` or `tests.md`; it needs browsers and credentials, so it is not in CI, and the quality job checks that its cases still apply.
- **Probes, not yet evals:** `add-page-object`, verified by a run, not gated.
- **Not measured yet:** real failed nightlies over time. Every real nightly so far was green, and a CI run's report can only be fetched for 14 days, so a failing one has to be added as it happens.

## 6. Choosing the mechanism

| Need                                | Mechanism              | Here                                                      |
| ----------------------------------- | ---------------------- | --------------------------------------------------------- |
| A rule that must hold in every task | Root `CLAUDE.md`       | Guardrails, commands, architecture                        |
| A rule for one area of the code     | Path-scoped rule       | `.claude/rules/pages.md`, `tests.md`, `ci.md`             |
| A repeatable procedure              | Skill                  | `write-test`, `add-page-object`, `/check`, `/fix-test`    |
| Its own context, tools or model     | Subagent               | `triage`, `locator-reviewer` (Haiku), `test-gap-analyzer` |
| Something that must never happen    | Hook or deny rule      | `block-test-weakening`, `Read(./.env)` deny               |
| Data or actions from another system | MCP server             | `qa` (known bugs, CI reports), Playwright                 |
| Work with nobody watching           | Headless with a schema | Nightly triage, AI review                                 |
| Several agents at once              | Worktrees              | `.claude/worktrees/`, `.worktreeinclude`                  |
| Knowing whether any of it works     | Eval                   | The triage, fix-loop, review and write-test evals         |

## 7. Next steps

1. **Real failed nightlies:** add each one to the whole-run eval (`source.ciRun`) within the 14 days its report can be fetched, labelled after the fact. (Whole-run cases and cases where the obvious reading is wrong are in now.)
2. **Write-test cases that need the skill:** a behaviour that needs a new locator verified on the live app, or a page state for an accessibility scan. On today's 6 cases a plain prompt did as well as `/write-test`. (`/fix-test`, the locator review and `write-test` have evals now; `add-page-object` does not.)
3. **The CI triage model:** stays Sonnet. Haiku matched it on single failures. On whole runs it made 3 critical errors in 21 runs before the report contract was made explicit, among them a green verdict on a red run. After that change it made none, but still failed the gate: in 2 of 21 runs it left out a known-bug id. The saving is about $0.05 per nightly. Revisit when a new model is out, with both evals.
4. **Review for untrusted contributors:** run the tooling from the base branch and treat the pull request's checkout as data only.
5. **Coverage:** rerun `test-gap-analyzer` for the next gap. (The Dynamic Catalog, the one it ranked first, is covered now.)
